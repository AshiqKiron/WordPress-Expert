# WordPress Community & Governance Documentation

## Documentation Contributor Handbook
### Overview
Guidelines for contributing to official WordPress documentation: structure, tone, markdown standards, review workflows, and team coordination.

### Core Sections
- **Documentation Structure & Navigation**: Handbook hierarchy, sidebar organization, breadcrumb mapping
- **Writing Style & Technical Accuracy**: Clear headings, active voice, version notes, code accuracy
- **Markdown & Formatting Rules**: Fenced blocks, header levels, lists, tables, link syntax
- **Code Example Standards**: Language tags, security patterns, version compatibility, copy-paste readiness
- **Review & Approval Process**: Draft → PR → Review → Merge → Deploy, reviewer roles, feedback cycles
- **Translation & Localization Workflow**: GlotPress integration, string extraction, translator guidelines
- **Contributor Onboarding & Meetings**: Slack channels, weekly docs meetings, mentorship, first-issue guides

## Documentation Licensing Guide
### Overview
Official licensing policy for WordPress documentation content and code snippets.

### Core Sections
- **CC0 Public Domain Dedication**: Text content waiver, no attribution required, commercial use permitted
- **GPLv2+ for Code Examples**: Copyleft requirement, derivative works, distribution terms
- **Attribution Requirements**: Recommended credit format, trademark usage, branding guidelines
- **Derivative Works & Redistribution**: Modification rights, license compatibility, fork policies
- **Third-Party Content Guidelines**: External links, embedded media, copyright clearance
- **Compliance & Enforcement**: DMCA process, violation reporting, license verification

## WordPress Software License (GPLv2+)
### Overview
Full text and explanation of the GNU General Public License version 2 (or later) under which WordPress is distributed.

### Core Sections
- **License Preamble**: Philosophy, freedom definitions, community values
- **Terms & Conditions**: Source code distribution, modification rights, derivative works
- **Distribution Requirements**: Provide source, preserve notices, include license text
- **Derivative Works & Copyleft**: Viral licensing, plugin/theme implications, linking exceptions
- **No Warranty & Liability Disclaimer**: "AS IS" clause, limitation of liability, jurisdiction
- **Official Translation Notes**: Non-binding translations, authoritative English text, version tracking

## Core Developer Handbook
### Overview
Workflow and contribution guidelines for WordPress Core development: patch submission, testing, ticket triage, release cycles, and team communication.

### Core Sections
- **Getting Started with Core Contributing**: Local setup, `wp-env`, PHPUnit, coding standards
- **Trac & Ticket Workflow**: Bug/feature/enhancement types, component assignment, priority/severity
- **Patch Submission & Code Review**: Git SVN bridge, diff generation, reviewer feedback, iteration
- **Testing & Automated CI**: PHPUnit, Selenium, PHPStan, GitHub Actions, performance benchmarks
- **Release Schedule & Milestones**: Beta/RC timeline, feature freeze, string freeze, release party
- **Team Meetings & Slack Channels**: #core, #core-dev, #core-editor, #core-restapi, meeting cadence
- **Governance & Decision Making**: Release lead rotation, RFC process, consensus model, conflict resolution

> 📝 **Where to Update**: Refresh meeting schedules, Slack channel names, and Trac workflows when Core team reorganizes. Update licensing references if CC0/GPL interpretations evolve. Add new contributor onboarding steps as tooling changes.
